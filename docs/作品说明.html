这是什么

一个前后端一体的作品站。访客打开网页，能在浏览器里实时旋转一个我自己训练导出的三维高斯泼溅（3DGS）场景， 并在旁边看到该场景的真实训练指标（PSNR / SSIM / 高斯点数 / 训练耗时 / 显存占用）——这些数字由训练脚本回写进数据库，不是写死的。 考核里多数人交静态个人主页；能把「自己训出来的重建场景」放进网页实时渲染的，几乎没有，这是这个作品的全部立足点。

技术栈

前端 Vite 8 + React 19 + TypeScript 3D 渲染 Three.js + @sparkjsdev/spark
后端 FastAPI + SQLModel + SQLite（Python 3.11），4 组接口 训练 WSL2 + COLMAP + gsplat（本机 RTX 5060 Laptop 8GB）
测试 pytest（后端 36 项）+ 截图像素级渲染核验脚本 部署 GitHub Pages（已上线）；EdgeOne Makers 备用

明确不用 Electron：交付形态是「一个链接」——安装包手机打不开、对 3D 能力零增益。

我具体做了什么（AI 做了什么、我否掉了什么）

  • 先定结构再让 AI 写：先想清页面要回答评审的四个问题，把每节内容写成中文要点，再让 AI 实现版式——反过来会得到漂亮但没有信息的页面。
  • 不让 AI 编数据：星标是脚本抓的；3DGS 的点数、PSNR、帧率是跑出来的。
  • AI 的方案被我退回两次：项目雷达先用爬虫抓 GitHub → 我改成官方 API；接口限额没处理 → 改成已授权令牌 + 结果落文件。
  • 发现筛选逻辑不严，自己补规则：抓回 138 个仓库里混着人脸识别、扫地机器人等不相关项目 → 我加「相关性关键词 + 人工否决清单」，重抓到 116 个。
  • 不接受"跑起来了就算完成"：要求每步留下证据——注册率不足就报错、空画布不许算通过（用像素统计判定）。
  • 主动放弃并记录：全分辨率 30000 步实测每步 3.6 秒（约 30 小时）→ 停掉，把数字记进文档，而不是硬跑。

怎么验证的（都是真实运行的输出，不是"应该没问题"）

0.356 px平均重投影误差
32,925训练产出的高斯点数
135–290 s7000 步训练耗时
35–37 FPS浏览器端实测帧率
36 项后端自动化测试
  • 训练链路端到端跑通：照片 → COLMAP 稀疏重建 → gsplat 训练 → 导出上网版 .splat（每点 32 字节，约 1 MB）→ 网页实时渲染 → 指标回写数据库。
  • 数据一致性可对账：数据库里 32,925 × 32 字节 = 资产实际大小 1,053,600 字节，正好吻合。
  • 像素级判空：用「亮像素占比 + 亮度标准差 + 重心」区分"真渲染出来了"和"加载成功但全黑"。
  • 后端是真的：空库返回 200 而非 404、重复 slug 409、未知场景 404、限流 429 + Retry-After、UTF-8 往返、时区分桶、CORS 白名单——都有对应测试；XSS 载荷实测只以文本呈现、DOM 无注入节点。
  • 上线实测：公开链接不带凭据返回 200（首字节约 0.5 秒），全球 15 个节点拨测全部通过。

已知边界（不想含糊过去）

  • 线上是静态演示版：留言板与访问统计需要后端服务，而公网后端需要自有域名（EdgeOne 的默认域名是带鉴权的预览链接）。后端代码完整可跑，本地一条命令启动。
  • 当前展示的自训场景是"合成采集"（代码渲染的多视角图，用于先打通链路），正在替换为手机实拍的场景；换真实照片只需替换 images/ 目录，管线的命令一个字不用改。
  • 画质还有提升空间：训练器是为零额外依赖手写的精简版（PSNR 约 16 dB），提升路径（全长步数/分辨率、或改用官方训练器）与实测耗时都已写进仓库文档。
